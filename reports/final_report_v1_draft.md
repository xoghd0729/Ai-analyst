# 1. 서론

## 1.1 연구 배경 및 동기

대한민국은 노인 빈곤율 부문에서 OECD 회원국 중 최하위권에 머물러 있다. 통계청에 따르면 2022년 기준 65세 이상 노인의 상대적 빈곤율은 43.4%로, OECD 평균(14.2%)을 크게 상회한다 [1]. 동시에 국민연금의 소득대체율은 약 40% 수준에 그쳐, 은퇴 이후 안정적인 현금흐름을 확보하기 위해서는 개인의 추가적인 자산 운용이 필수적인 상황이다.

그러나 현존하는 자산관리 서비스들은 세 가지 한계를 가진다. 첫째, **수익률 중심의 정보 제공**에 머물러 있어 사용자가 실제로 필요로 하는 "월별 현금흐름" 관점의 의사결정을 도와주지 못한다. 둘째, **자산 1억 원 미만 고객을 사실상 외면**하는 구조로 작동한다. 미래에셋·삼성·KB와 같은 대형 자산관리사의 RBA(Robo Advisory) 서비스는 대부분 일정 규모 이상의 자산 보유자를 전제로 설계되어 있다. 셋째, **한국 세법 환경에 특화되지 않은** 서비스가 다수다. Wealthfront, Betterment와 같은 해외 자산관리 서비스는 한국의 금융소득종합과세, ISA 계좌, 연금저축의 세제 혜택을 반영하지 못한다.

본 연구는 이러한 공백을 메우기 위해, **"50세에 월 200만 원의 배당을 받으려면 지금 얼마를 투자해야 하는가?"** 라는 사용자의 현실적인 질문에 역산(逆算) 방식으로 답하는 시스템을 설계한다.

## 1.2 문제 정의

본 시스템이 해결하고자 하는 핵심 문제는 다음과 같다.

**핵심 질문**: 사용자가 입력한 (나이, 적립 가능 금액, 목표 월 배당)을 기반으로, AI 파이프라인이 다음 네 가지를 통합적으로 수행한다.

1. **설계(Design)** — 미래 월급형 현금흐름의 시뮬레이션 (FIRE 역산, Monte Carlo)
2. **분석(Analyze)** — 종목·포트폴리오의 진단 (ML 분류, SHAP 설명, 21년 백테스팅)
3. **방어(Defend)** — Yield Trap 회피, 세금 최적화, 스트레스 테스트
4. **관리(Manage)** — 시간 흐름에 따른 리밸런싱, 알림, 모니터링

기존 서비스는 forward simulation(원금 입력 → 미래 결과)에 머무르는 반면, 본 시스템은 **backward inversion**(목표 미래 → 현재 행동)을 함께 제공한다는 점이 결정적 차별점이다.

## 1.4 관련 연구 및 시장 분석

본 연구는 다음과 같은 기존 이론과 서비스에 기반한다.

**이론적 배경**

- **현대 포트폴리오 이론(MPT)** [2] — 평균-분산 최적화의 기반. 자산 분산을 통한 위험 감소.
- **자본자산가격결정모형(CAPM)** [3] — 위험조정 수익률(Sharpe Ratio)의 이론적 기반.
- **FIRE 운동(Financial Independence, Retire Early)** [4] — "4% 인출 규칙"에 따라 연 4%를 인출하면 자산이 영구히 유지된다는 원칙.
- **Monte Carlo Simulation in Finance** [5] — 단일 예측이 아닌 확률 분포(P10/P50/P90)로 미래를 표현.
- **SHAP (SHapley Additive exPlanations)** [6] — ML 모델의 예측을 피처 단위로 분해하여 설명 가능성 확보.
- **행동재무학** [7] — Kahneman & Tversky의 손실 회피 등 인지 편향 이론.

## 2.2 Pipe-and-Filter 18-필터 파이프라인

본 시스템의 핵심은 18개의 독립적인 필터(Filter) 클래스로 구성된 Pipe-and-Filter 아키텍처다. 이는 SOLID 원칙 중 단일 책임 원칙(SRP)을 엄격히 적용한 결과로, 리팩토링 이전의 1,960줄짜리 단일 함수(`recommend_portfolio()`)를 18개의 작은 모듈로 분리한 것이다.

```python
# api/pipeline/runner.py 의 실행 순서
MacroRegime → AxisWeight → AssetPicker → WeightAllocator
  → Summarize → Projection → Rebalancing → StressTest
  → SectorExposure → Calendar → RiskAlert → FireEngine
  → MonteCarlo → TaxOptimizer → BehavioralFinance
  → YieldTrapDetector → PortfolioHealth → SHAPExplainer
  → Storytelling
```

각 필터는 `BaseFilter` 추상 클래스를 상속받으며, 공유 상태인 `PipelineContext`를 읽고 쓰는 방식으로 작동한다.

```python
class BaseFilter:
    name: str = "BaseFilter"

    def process(self, ctx: PipelineContext) -> None:
        """ctx에서 이전 필터 결과를 읽고, 자신의 결과를 ctx에 기록."""
        raise NotImplementedError

class RecommendationPipeline:
    def execute(self) -> PipelineContext:
        for filt in self.filters:
            try:
                filt.process(self.ctx)
            except Exception as exc:
                log.error("Pipeline step %s failed: %s", filt.name, exc)
                self.ctx.add_error(filt.name, str(exc))
        return self.ctx
```

이 구조의 장점은 다음과 같다.

1. **부분 실패에 강건함(graceful degradation)** — 한 필터가 예외를 발생시켜도 다른 필터는 계속 동작한다. 사용자는 항상 어떤 형태로든 응답을 받는다.
2. **테스트 용이성** — 각 필터를 독립적으로 단위 테스트할 수 있다.
3. **확장성** — 새로운 분석 기능을 추가할 때 새 Filter 클래스 하나만 작성하고 실행 순서에 등록하면 된다. 본 캡스톤 기간 동안 `YieldTrapDetector` 필터가 이 방식으로 추가되었다.

## 3.1 FIRE 역산 엔진

본 시스템의 출발점이 되는 모듈로, "목표 월 배당 × 12"를 평균 세후 수익률로 나누어 필요 원금을 역산한다.

**수식**:

```
필요원금 = (목표월배당 × 12) ÷ 세후수익률

누적금액(t) = 원금 × (1+r)^t
           + 월적립 × [((1+r/12)^(12t) − 1) / (r/12)]

도달연도 = min{ t | 누적금액(t) ≥ 필요원금 }
```

여기서 `r`은 세후 평균 수익률(예: 3.5%)이며, 인플레이션 보정을 위해 `r_real = r − cpi`로 조정한 실질 수익률을 적용할 수 있다.

**구현 위치**: `utils/fire_engine.py:calc_fire_engine()`

**예시 출력** (28세 윤지, 시드 1,000만 원, 월 적립 100만 원, 목표 월 배당 200만 원):

```
필요 원금: 6.86억 원 (월 200만 × 12 / 3.5%)
P50 시나리오 도달: 50세
P10 시나리오 도달: 53세 (보수)
P90 시나리오 도달: 47세 (낙관)
```

(다음 페이지에 3.2 Monte Carlo, 3.3 Yield Trap 자동 감지가 이어지며, D6 작업에서 섹션 4~7을 추가한다.)
