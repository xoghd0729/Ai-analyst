AI 소득 지속성 분석 시스템 — 전체 구조 설명서

"배당 삭감을 예측해서, 그 위험을 '미래 월소득이 끊길 위험'으로 바꾸고, 목표 달성까지 설계해 주는 시스템"
이 문서는 데이터 선정부터 XGBoost·SHAP, 추천 파이프라인, 화면까지 한 흐름으로 설명한다.


────────────────────────────────────────
0. 한 장 요약 (전체 흐름)
────────────────────────────────────────

데이터 수집(DART·yfinance)
  → 피처 13개 + 라벨(INTACT/WEAKENING/BROKEN)
  → XGBoost 3-클래스 학습 (GroupKFold 검증 PR-AUC 0.801)
  → SHAP로 "왜 위험한가" 설명
  → 추천 파이프라인(20개 필터)이 종목 선별·비중 배분
  → FIRE 역산 · Monte Carlo · 생존확률로 "언제·얼마나 오래"를 계산
  → React 대시보드로 출력

핵심 아이디어: 기존 투자 서비스가 보는 위험은 '주가 변동성(Volatility)'이지만,
이 시스템이 보는 위험은 '내 월배당 소득이 끊길 위험(Income Risk)'이다.


────────────────────────────────────────
1. 데이터 선정 — 무엇을, 왜, 어디서
────────────────────────────────────────

(1) 왜 이 데이터인가
목표는 "이 종목이 앞으로 배당을 삭감할까?"를 맞히는 것이다. 따라서 주가가 아니라
'배당을 지급할 현금 여력'을 보여주는 재무 데이터가 필요했다.

(2) 국내 데이터 — DART OpenAPI
- 출처: 금융감독원 전자공시(DART) Open API
- 기간: 2013 ~ 2025 (다년도)
- 규모: 210개 종목, 1,679개 관측치 (종목 × 연도 = 1행)
- 수집 방식: build_dataset.py 가 종목별로 재무제표를 받아 적재.
  중간에 끊겨도 이어받도록 종목 단위 체크포인트를 둠.
- 시행착오: 처음엔 pykrx·FinanceDataReader(거래소 스크래핑)를 썼으나 로그인·차단으로
  실패 → 정상 동작하는 DART API로 전환.

(3) 미국 데이터 — yfinance
- 미국 배당주는 대부분 배당귀족·배당왕이라 '삭감' 사례가 약 4%로 극히 드물다.
- 실제로 학습해 보니 PR-AUC 0.05 (사실상 무의미) → 머신러닝 부적합 판단.
- 결론: 미국은 ML 대신 룰 기반 안정성 평가로 분리. "데이터가 방법을 결정한다."

(4) 피처 13개 (모델 입력)
배당 지급은 결국 '버는 현금 ≥ 나가는 배당'인지의 문제다. 그래서 현금흐름·배당·재무
건전성 지표로 구성했다. (주의: ROE·EPS 같은 수익성 지표가 아니라 현금흐름 중심)

  · 현금흐름: 영업현금흐름, 잉여현금흐름(FCF), 설비투자(CAPEX), 배당지급액, FCF 음수여부
  · 비율:     배당성향, 배당커버리지, 배당/영업현금흐름, 영업현금흐름/설비투자
  · 재무:     부채비율, 이자보상배율, 매출성장률
  · 배당:     주당배당금 전년 대비 증감률(DPS YoY)

(5) 라벨 — label3 (정답)
다음 시점 배당 상태를 3단계로 라벨링.
  · 0 = INTACT   (유지)
  · 1 = WEAKENING (약화 — 줄어들 조짐)
  · 2 = BROKEN   (삭감)
전체의 약 22%가 위험(WEAKENING+BROKEN). 즉 '드문 사건'이라 불균형 데이터다.


────────────────────────────────────────
2. 모델 — XGBoost 3-클래스
────────────────────────────────────────

(1) 구조
- sklearn Pipeline = SimpleImputer(결측 보정) → XGBoost(3-클래스 분류)
- 저장 파일: models/kr_3class_model.pkl
- 출력: 한 종목에 대해 INTACT / WEAKENING / BROKEN 확률

(2) 왜 XGBoost인가 (모델 비교 — 동일 GroupKFold·PR-AUC)
  · 무작위 기준선   : 0.385
  · Logistic Reg.   : 0.670  (선형 → 한계)
  · Random Forest   : 0.799
  · Gradient Boost  : 0.801
  · XGBoost(채택)   : 0.801  (ROC-AUC 최상위)
선형 모델은 0.67로 부족, 트리 앙상블은 0.80 부근으로 수렴.
그중 XGBoost를 택한 이유: ROC-AUC 최상위 + SHAP 설명 호환 + 클래스 불균형 보정(가중)이 쉬움.

(3) 왜 정확도(Accuracy)가 아니라 PR-AUC인가
삭감이 22%뿐이라 "전부 INTACT라고 찍어도 정확도 78%"가 나온다 → 정확도는 속는다.
PR-AUC는 '드문 위험을 실제로 잡아내는 능력'을 측정해서 정직하다.

(4) 검증 — 두 단계로 "신뢰도"를 확보
  ① GroupKFold (종목 단위 교차검증)
     - 같은 종목의 여러 연도가 학습/검증에 동시에 들어가면 '커닝'(데이터 누수)이 된다.
     - 종목 단위로 분리 → 처음 보는 종목에도 일반화. 거품 제거 후 PR-AUC 0.801.
  ② Out-of-Time Forward Backtest (미래 검증)
     - 특정 연도 이전 데이터만으로 학습 → 그 다음 해를 예측 (2019~2024 반복).
     - 결과: PR-AUC 0.76 ~ 0.86 (코로나 2020 포함해도 안정). 전체 0.803.
     - 의미: "처음 보는 미래"에도 작동함을 입증.

(5) 실용 지표
위험 확률 상위 20% 종목을 경고했을 때 정밀도 0.96
→ "위험하다"고 경고한 종목의 96%가 실제 위험. 경고 시스템으로 쓸만하다.


────────────────────────────────────────
3. SHAP — "왜 위험한가"를 설명 (XAI)
────────────────────────────────────────

- XGBoost는 블랙박스다. SHAP TreeExplainer로 각 지표가 위험 판단에 얼마나 기여했는지를 분해.
- 전역 중요도: 주당배당금 증감률이 61.6%로 압도적 1위 (직전 배당 흐름의 변화가 가장 강한 삭감 신호).
  이어 배당지급액·부채비율·배당커버리지 순.
- API: GET /api/stock/{종목코드}/explain
  → cut_prob(삭감 위험확률), top_risk_factors(지표별 위험↑/안전), summary
- 견고성: DB(PostgreSQL)가 꺼져 있으면 학습 데이터(dividend_dataset.csv)로 폴백하도록 처리.
  (개발 중 "DB엔 일부 종목이 없어 SHAP가 안 뜨던 문제"를 CSV 폴백으로 해결)
- 화면: 종목 선택 → 삭감 위험확률 + 지표 막대 + 'AI 설명'(지표 의미) + '현실에서 이 종목은'(섹터 맥락)


────────────────────────────────────────
4. 추천 파이프라인 — Pipe-and-Filter (20개 필터)
────────────────────────────────────────

(1) 설계 사상
하나의 거대한 함수 대신, 기능을 독립적인 '필터'로 쪼개 순서대로 연결한다.
- 공유 상태(PipelineContext)를 게시판처럼 두고, 각 필터가 읽고 자기 결과를 기록.
- 한 필터가 실패해도 그 결과만 비우고 다음으로 진행(오류 격리).
- pytest 149개 테스트로 검증.

(2) 입력 (PortfolioRequest)
나이 · 월 적립금 · 적립 증가율 · 투자금 · 목표 월배당 · 투자 성향 · 페르소나 · 목표 FIRE 나이

(3) 실행 순서 (요약)
  거시레짐 → 축가중(4축 비중) → 자산선별 → 비중배분 →
  요약 → 성장projection → 리밸런싱 → 스트레스테스트 → 섹터노출 → 배당캘린더 →
  위험경고/ISA → FIRE역산 → MonteCarlo → 생존확률 →
  세금최적화 → 행동편향 → 고배당함정 → 건강도 → SHAP설명 → 스토리텔링

(4) 자산 선별 (AssetPickerFilter) — 어디서 종목이 나오나
- 한국 개별주: ranking.csv(배당 스코어러로 만든 43종목 풀)에서 선별.
  · DANGER(함정) 제외, 점수 ≥ 50 필터
  · 성향별: 안정형=우량+ML INTACT만 / 공격형=고수익률 허용
  · 나이 기반 틸트: 젊으면 성장 가점, 나이 들면 안정 가점 → 나이대별로 종목이 달라짐
  · 개수: 9~10개 (예전엔 5개 고정이라 항상 같았던 버그를 수정)
- 미국 개별주(rule 기반) · ETF(배당/성장/방어) · 리츠도 각 풀에서 선별

(5) 비중 배분 (WeightAllocatorFilter)
- 4축(한국·미국·ETF·방어 등) 비중 × 종목 점수 비례로 분배
- 단일 종목 8% 상한(한 종목 쏠림 방지) → 초과분 재분배
- 최종 정규화 + 반올림 잔차 보정 → 비중 합 정확히 100.0%
- 결과: 약 20~25개 자산. 단, '실제 매수할 핵심'은 상위 5~8개, 나머지는 충격 분산용 소액.


────────────────────────────────────────
5. 분석 레이어 — "언제·얼마나 오래"
────────────────────────────────────────

(1) FIRE 엔진 (목표 달성 역산)
- 입력(투자금·적립·증가율·수익률·물가)으로 목표 월배당 달성 나이를 역산.
- 목표별 나이: Lean(월120) / 배당목표(사용자값) / 일반(월250) / Fat(월400)
- 물가(연 2.5%)를 반영한 실질 기준. 가정을 바꾸면 즉시 재계산.
- (화면 일관성) 헤드라인·여정·달성근거·FIRE한눈에의 '달성 나이'를 한 엔진으로 통일.

(2) Monte Carlo (1,000회 시뮬레이션)
- 수익률 변동을 반영해 20년 후 월배당의 P10/P50/P90(비관/중간/낙관)을 산출.
- 목표 달성 확률을 제공 (적립 포함 기준 / 현재 자산만 유지 기준을 구분 표기).

(3) 생존확률 / 소득 지속성 점수 ★ 이 프로젝트의 핵심 ★
- 종목별 ML 삭감확률 + 섹터·국가 단위 상관충격(동시에 흔들리는 위험) + Monte Carlo를 통합.
- 출력: "이 월배당이 20년 뒤에도 나올 확률(생존확률)", 소득 지속성 점수(0~100), 건강도.
- 위험 기여도: 단순 '비중'이 아니라 '실제 위험 기여'를 계산 → 비중 대비 숨은 집중을 드러냄.
  (예: 국내 개별주가 비중 20%지만 위험 기여 35% — 동시 충격에 취약)

(4) 그 외
- 세금 최적화: 2026 세법(ISA 한도 4,000 / 비과세 500·1,000) 반영
- 행동편향: 홈바이어스·집중·고배당 착시 등 진단
- 21년 백테스트: 2005~2024 실제 데이터(2008·2020 위기 포함)로 CAGR/MDD/Sharpe/Sortino


────────────────────────────────────────
6. 시스템 구성 (기술 스택)
────────────────────────────────────────

- 백엔드: FastAPI (uvicorn). 추천 = Pipe-and-Filter 파이프라인.
- 저장소: PostgreSQL(SQLAlchemy) + JSON/CSV 파일 폴백 (DB 없어도 동작).
- ML: XGBoost + scikit-learn Pipeline, SHAP TreeExplainer.
- 프론트엔드: React + Vite + Recharts.
- 인증: 파일 기반 로그인(비밀번호 SHA-256 해시) — 로그인 없이도 모든 분석 사용 가능, 로그인 시 저장·변화추적.
- 테스트: pytest 149개.

화면 흐름:
  로그인 게이트(건너뛰기 가능) → 입력 → 헤드라인(달성 나이·진행률) → 추천 포트폴리오(핵심 5~8 + 분산)
  → SHAP 근거 → 4축 배분 → 복리 성장 → 월별 캘린더 → Monte Carlo → 소득 지속성 → 백테스트


────────────────────────────────────────
7. 핵심 차별점 (발표에서 반복할 한 문장)
────────────────────────────────────────

기존: 재무 위험 = Volatility(주가가 얼마나 흔들리나) — 내 목표·소득과 무관
본 시스템: 소득 위험 = Income Risk(내 월소득이 끊길 위험) — 목표·생존확률·FIRE와 직접 연결

  배당 삭감 예측  →  포트폴리오 생존확률  →  FIRE 목표 역산  →  현금흐름 관리

→ "배당 종목 추천기가 아니라, 소득 지속성 분석 시스템이다."
→ 기존 서비스는 '무엇을 살까'를 돕고, 본 시스템은 '언제 목표를 달성할까'를 계산한다.


────────────────────────────────────────
8. 개발 중 해결한 주요 문제 (시행착오 — 보고서용)
────────────────────────────────────────

1. KRX 스크래핑 차단 → DART API 전환 (+ 체크포인트)
2. 데이터 누수(시계열 분할이 사실상 그룹 누수) → 종목 단위 GroupKFold → 정직한 0.80
3. 미국 ML 부적합(삭감 4%, PR-AUC 0.05) → 룰 기반 분리
4. 지표 기준 충돌(100% vs 0%) → 기준 명시 + 단일 헤드라인 통합
5. DB↔CSV 불일치로 SHAP 미출력 → CSV 폴백 로직 추가(XAI 정상화)
6. 한국 개별주 5개 고정 버그(호출부만 age 인자 추가) → 함수 시그니처 수정 → 9개·나이별 변형
7. 비중 합 99~100% 흔들림 → 반올림 잔차 보정 → 정확히 100.0%
8. FIRE 달성 나이가 화면마다 달랐던 문제 → 단일 엔진(calcCompoundGrowth)으로 통일
