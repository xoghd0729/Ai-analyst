AI Cashflow OS — 방학 업그레이드 로드맵 v2 (방향성 전환)

작성 배경: 취업/캡스톤 포트폴리오 관점에서 "XGBoost 분류"는 ML 입문 수준으로 읽힘(교수 #1).
검증 결과: 모델을 CatBoost·LightGBM 등으로 바꿔도 forward 성능은 0.24~0.26로 동일 →
모델이 아니라 '방법론'과 '데이터'를 바꿔야 한다.


────────────────────────────────────────
0. 새 정체성 (방향성 전환)
────────────────────────────────────────

이전: "XGBoost로 배당 삭감을 분류하는 예측기"  (ML 입문 인상)
이후: "은행급 신용위험 방법론(생존분석·구조모형)을 배당 소득에 이식한
       Dividend Survival Analysis 시스템"

핵심 전환: 분류(좋다/나쁘다) → 생존(언제 끊기나, lifetime PD).
이 한 줄이 #1("평범")을 정면으로 깬다 — ML 모델 하나가 아니라 금융공학 방법론을 가져온 것.

이력서 한 줄(목표):
"은행 IFRS 9 lifetime PD에 쓰는 생존분석(Cox·discrete-time hazard)과 Merton 구조모형을
 배당 소득 위험에 적용. 신용등급 전이(Markov)로 다중상태 모델링, Altman·Ohlson 고전 대비
 벤치마크, DeepSurv로 확장. XAI는 SHAP/EBM."


────────────────────────────────────────
1. 솔직한 현실 (먼저 인지)
────────────────────────────────────────

- 보고서의 PR-AUC 0.80은 대부분 'BROKEN(이미 줄어든 배당) 탐지'(0.97)에서 옴.
  진짜 forward 예측(WEAKENING, 내년 삭감)은 0.25로 약함 — 모델 6종 모두 동일.
- 따라서: 모델 교체만으로 성능은 안 오른다. 성능은 (a) 데이터 규모·시장신호, (b) 문제 재정의에서 온다.
- 포트폴리오 가치는 '높은 정확도'가 아니라 '방법론의 깊이 + 정직한 검증'에서 온다.
  (결과는 정직하게 쓰되, 방법론으로 차별화한다.)


────────────────────────────────────────
2. 새 모델 스택 (포트폴리오 임팩트 순)
────────────────────────────────────────

A. 생존분석 (핵심) — IFRS 9 lifetime PD 차용
   · 이산시간 hazard (cloglog/logit GLM) — 연도별 데이터에 정확히 맞음
   · Cox 비례위험(PH) — 표준, concordance(C-index)로 평가
   · 출력: 종목별 '배당 생존곡선'(1/3/5년 생존확률) → 앱의 생존확률과 직결

B. Merton Distance-to-Default — 시장형 구조모형
   · 주가·자산변동성으로 '부도(=배당위험) 거리' 계산
   · 회계 기반(현재)에 '시장 신호'를 더함 → "주가 빠져도" 질문에 답
   · 회계 단독보다 우수하다는 연구 다수 → 진짜 신호 보강 후보

C. Markov 전이행렬 — 신용등급 전이
   · INTACT→WEAKENING→BROKEN = 다중상태 전이로 모델링
   · 연도별 전이확률 행렬 → "1년 후 등급 분포" 산출

D. DeepSurv / DeepHit — 신경망 생존모형 (딥러닝 크레딧)
   · 비선형·경쟁위험까지. 데이터 충분해지면.

E. 벤치마크: Altman Z / Ohlson O / Gradient Boosting
   · "우리 생존모형이 고전·ML 대비 얼마나 낫나"를 표로 — 연구적 엄밀성

F. 설명: SHAP / EBM(Explainable Boosting Machine, 글래스박스)


────────────────────────────────────────
3. 단계별 실행 (~9월 초)
────────────────────────────────────────

Phase 1 (모델 방법론 전환) — 6~7월
  1. 생존 데이터 정식 구성 (time-to-first-cut, time-varying 공변량, 누수 차단=lagged)
  2. 이산시간 hazard + Cox PH 구현, C-index 평가, 생존곡선 출력
  3. Altman Z / Ohlson O 구현 → 벤치마크 표
  4. 앱의 '소득 생존확률'을 이 생존곡선으로 교체 연결

Phase 2 (데이터 + 시장신호) — 7~8월  ※ 성능은 여기서 나온다
  1. 데이터 규모: 종목·연도 확대 (한국 + 미국 SEC EDGAR, 위기연도 포함)
  2. Merton DtD: 주가·변동성 데이터로 시장형 신호 추가
  3. 거시변수(금리·CPI·VIX): hazard 공변량 + Monte Carlo regime
  4. DART 증분 수집 파이프라인 + 버전관리

Phase 3 (시스템화 + Agent) — 8~9월
  1. 자동 모니터링·알림·리밸런싱 (운영 시스템)
  2. LLM Agent: 자연어 → 검증된 도구(생존PD·Merton·FIRE) 호출 → 리포트


────────────────────────────────────────
4. 교수 7개 → 매핑
────────────────────────────────────────

| # | 피드백 | 해결 |
|---|---|---|
| 1 | XGBoost 평범 | 생존분석·Merton·Markov로 방법론 전환 + 다모델 벤치마크 |
| 2 | 왜 LLM 아닌가 | 운영 시스템 + 검증엔진 호출 Agent (Phase 3) |
| 3 | 미국도 동일 수준 | SEC EDGAR + Merton(시장형은 국가 무관) (Phase 2) |
| 4 | 신규 상장 Cold Start | 업종 평균/유사기업 + Merton(주가만 있으면 가능) |
| 5 | DART 갱신 | 증분 수집·버전관리 (Phase 2) |
| 6 | 거시변수 | hazard 공변량 + MC regime (Phase 2) |
| 7 | 규모 작음 | 방법론×데이터×시스템 전 영역 확장 |


────────────────────────────────────────
5. 한 줄 결론
────────────────────────────────────────

모델을 바꾸는 게 아니라 '문제를 분류에서 생존으로' 바꾼다.
정확도는 데이터·시장신호(Merton)로 끌어올리고, 포트폴리오 가치는
'은행급 신용위험 방법론을 배당에 이식했다'는 방법론 깊이에서 나온다.
