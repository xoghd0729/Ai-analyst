## 1. 제품 정체성

**AI Cashflow OS**는 AI 기반 개인 현금흐름 설계 및 시뮬레이션 플랫폼이다.

사용자의 나이, 소득, 투자 가능 자산, 월 저축액, 목표 현금흐름, 위험 성향을 입력받아:

- 목표 달성 경로(FIRE 역산, 배당 포트폴리오 설계)를 제시하고
- 다양한 시장 상황에서 그 계획의 지속 가능성을 분석하며
- 배당 지속 가능성에 관한 위험 신호를 보조적으로 제공한다.

**핵심 질문에 대한 답**:
- "50세에 월 200만원 받으려면 지금 얼마를 투자해야 하나?" → FIRE 역산
- "현재 저축 속도로 경제적 독립까지 얼마나 걸리나?" → Monte Carlo 시뮬레이션
- "배당이 감소하거나 시장이 하락하면 계획이 얼마나 달라지나?" → 스트레스 테스트
- "세금과 자산 배분을 고려하면 실제 현금흐름은 얼마인가?" → 세금 최적화 + 비중 배분

**이 제품이 아닌 것**:
- 특정 종목의 배당 삭감 확률을 정밀하게 예측하는 ML 시스템이 아니다
- 검증 완료된 AI 예측 모델을 핵심 의사결정자로 내세우는 서비스가 아니다

## 3. 핵심 기능 3가지

### ① 현금흐름 설계 (Core)

목표 월 현금흐름을 역산하여 필요 투자금·달성 시점·자산 배분을 제시한다.

| 기능 | 구현 | 검증 상태 |
|-----|------|---------|
| FIRE 역산 (PMT 공식) | `utils/fire_engine.py` | 수학 공식 기반, 검증 가능 |
| 20년 배당 성장 시뮬레이션 | `utils/dividend_projection.py` | 가정값 명시 필요 |
| 세금 최적화 (2026 세법) | `utils/tax_optimizer.py` | ISA 4,000/500/1,000 고정 |
| 5축 자산 배분 | `api/pipeline/filters.py` | 아키타입별 내부 설계값 |

**주의**: FIRE 계산 결과는 수익률 가정에 민감하다. 수익률 가정을 실제보다 낙관적으로 설정해 결과를 좋게 보이게 만들지 않는다.

### ② 시뮬레이션 및 검증 (Core)

계획의 불확실성을 정량화하고 시나리오별 결과를 제공한다.

| 기능 | 구현 | 산출물 |
|-----|------|------|
| Monte Carlo (P10/P50/P90) | `utils/monte_carlo.py` | 시뮬레이션 신뢰구간 |
| 백테스트 (2015-2024) | `utils/backtesting.py` | CAGR, MDD, Sharpe |
| 스트레스 테스트 | `api/pipeline/filters.py` | 4개 시나리오 |
| 행동편향 탐지 | `utils/behavioral_finance.py` | 8가지 편향 경고 |

### ③ ML 위험 신호 (Auxiliary)

배당 지속 가능성에 관한 위험 신호를 제공하고, 정량 분석 결과를 자연어로 설명한다.

| 기능 | 구현 | 검증 상태 |
|-----|------|---------|
| TabPFN Survival hazard 점수 | `results/survival_pd_v4.json` | 단면 ROC 0.655 (2024년, n=62) — walk-forward 미완 |
| XGBoost ml_status 분류 | `data/ml_scoring_results.csv` | GroupKFold 시간 오염 확인 — 성능 수치 신뢰 불가 |
| SHAP 위험 요인 설명 | `utils/shap_explainer.py` | Rule-based attribution (실제 SHAP 아님) |
| 자연어 요약 | `utils/storytelling.py` | 규칙 기반 |

## 4. ML의 역할과 한계 (확정)

### 역할: 보조 위험 신호

ML 출력은 종목 선정의 주된 근거가 아니라 **재무 룰 기반 선별 이후의 위험 신호**다.

```
재무 건전성 룰 (1차)
  → 배당수익률·삭감이력·overall_score 기준 필터링
  ↓
ML 위험 신호 (2차, 보조)
  → TabPFN Survival hazard: 상대적 위험 순위 제공
  → XGBoost ml_status: 추가 참고 정보 (검증 대기)
  ↓
현금흐름 설계 엔진 (핵심)
  → FIRE 역산, Monte Carlo, 세금 최적화
```

### 한계: 현재 확정된 사실

| 항목 | 상태 | 근거 |
|-----|------|------|
| XGBoost 성능 수치 | 신뢰 불가 | GroupKFold 시간 오염 확인 (STEP 3) |
| TabPFN walk-forward 검증 | 미완 | HistGBM 기준 OOS ROC 0.5594 (STEP 4) |
| 70:30 가중치 | 플레이스홀더 | 유효 실험 근거 없음 (risk_engine.py 주석) |
| hazard_pct 해석 | 상대적 위험 순위 | 확률로 해석 불가 (uncalibrated) |
| ML 두 소스 간 일치도 | 불일치 존재 | 감사 결과: 포스코인터·한타·한진칼 등 |

### 한계: 현재 확정하면 안 되는 것

1. ML 모델이 배당 삭감을 안정적으로 예측한다고 주장하지 않는다
2. ML을 제거했을 때 제품 성능이 좋아진다고 미리 가정하지 않는다
3. 70:30 가중치가 최적이라고 단정하지 않는다
4. 금융지주 등 결측치 종목에 임의의 통과·탈락 기준을 적용하지 않는다
5. hazard_pct의 수치를 "XX% 배당삭감 확률"로 표현하지 않는다

## 5. 추천 엔진 설계 원칙

### 분리 원칙

추천 엔진의 각 단계를 다음 세 층으로 분리한다:

**Layer A: 재무 룰 기반 (검증 가능)**
- trap_level != DANGER
- overall_score ≥ 50
- dps_cuts_3y 이력
- 배당성향·안정성·재무 점수

이 층의 결과는 재무 데이터가 정확하면 재현 가능하다.

**Layer B: ML 위험 신호 (보조, 검증 대기)**
- TabPFN Survival hazard Hard Gate
- XGBoost ml_status (참고 표시)

이 층의 결과는 ML 성능에 의존한다. 어느 종목을 차단했는지 추적 가능하게 유지한다.

**Layer C: 현금흐름 최적화 (핵심)**
- 사용자 목표 역산
- 세후 수익률 배분
- FIRE 달성 시점 계산

이 층은 ML 성능과 무관하게 작동해야 한다.

### 결측치 원칙

- 재무 데이터 결측 = 위험의 증거도 안전의 증거도 아님
- NaN은 "검토 필요"로 분류, 자동 탈락·통과 금지
- 금융지주 업종의 payout_ratio 결측은 업종 특성으로 별도 표시

## 8. SurvivalFilter 표현 원칙 (v2.0.0 감사 결과 반영)

> 추가: 2026-10-03 (SurvivalFilter 헤드라인 검증 감사 후 확정)

다음 5개 원칙은 SurvivalFilter가 산출하는 "20년 배당 유지 비율" 지표를
사용자와 외부 파트너에게 정확하게 전달하기 위한 기준이다.

**원칙 1. 시뮬레이션 결과와 장기 예측 확률을 구분한다**

`survival_probability`는 2000회 Monte Carlo 시뮬레이션 중 20년 전기간
명목 월배당이 기준선 이상으로 유지된 경로의 비율이다. 이를 "배당이 유지될
확률"로 표현하지 않는다. 표현 형식: "시뮬레이션상 유지 비율 N%".

**원칙 2. ML 위험 신호가 기본 위험률로 대체되는 경우 ML이 직접 구동했다고 표현하지 않는다**

`_ml_hazard()`는 XGBoost P_BROKEN/P_WEAKENING이 종목별 기본 위험률(base_cut)을
초과할 때만 실질적으로 작동한다. 미초과 종목은 base_cut으로 폴백된다.
반환 필드 `ml_effective_count`가 0이면 "ML 위험 신호 미적용 — 기본 위험률 사용"으로
표시하고 ML이 구동했다고 표현하지 않는다.

**원칙 3. 유지 기준(threshold)이 사용자 목표인지 현재 명목 월배당의 80%인지 명확하게 표시한다**

기준선은 두 가지 경우 중 하나로 자동 결정된다:
- 사용자 목표(monthly_target)가 현재 월배당 이하면: `threshold_type = "user_target"`
- 그 외: `threshold_type = "current_80pct"` (초기 명목 월배당 × 0.80)

UI에서 "기준: 사용자 목표 N만원" 또는 "기준: 현재 배당의 80% (N만원)"을 함께 표시한다.
두 기준의 혼용 없이 적용된 기준 하나만 표시한다.

**원칙 4. 시뮬레이션 유지 비율과 실제 미래에 유지될 확률을 구분한다**

Monte Carlo 시뮬레이션은 모델 가정(배당성장률, 해저드율, 공통충격 파라미터)에
의존한다. 결과는 가정이 맞을 경우의 내부 일관성을 보여줄 뿐, 실제 미래
배당 유지를 보장하지 않는다. 보고 시 "모델 가정 하의 시뮬레이션 결과"임을 명시한다.

**원칙 5. 장기 실증 백테스트와 보정 검증 완료 전까지는 추정치라는 설명을 유지한다**

XGBoost(kr_3class_model.pkl)의 temporal contamination 확인,
TabPFN Survival의 walk-forward OOS ROC-AUC 0.56 기록,
Monte Carlo 파라미터의 미보정 상태 등을 고려할 때 현 단계의 수치는
추정치다. 검증 완료(walk-forward 8-fold 재실험 + 실증 배당 이력 대조)
이전에 "검증된 확률" 또는 "AI 예측" 표현을 사용하지 않는다.
