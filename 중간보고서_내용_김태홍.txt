────────────────────────────────────────────────────────────

프로젝트명: AI 현금흐름 운영체제 (AI Cashflow OS) v2.0
팀원: 김태홍 (202104011)


1. 프로젝트 개요

1.1 개요

국내 개인 투자자의 배당 투자 수요가 증가하고 있으나, 기존 금융 앱(뱅크샐러드, 토스증권 등)은 단순 포트폴리오 조회·추천에 머물러 있다. "50세에 월 200만원을 받으려면 지금 얼마를 투자해야 하나?"와 같은 목표 기반 역산형 질문에 답하는 시스템이 없으며, 외부 LLM(ChatGPT·Claude 등) 의존 시스템은 개인 재무 데이터가 외부 서버로 전송된다는 프라이버시 문제가 있다.

본 프로젝트는 목표 월배당을 입력하면 필요 투자금·월 적립금·FIRE 달성 나이를 역산하고, 로컬 LLM(Ollama qwen3:14b)으로 AI 분석을 제공하는 "AI 현금흐름 운영체제 v2.0"을 구축한다. 외부 API 의존성 없이 완전 로컬 환경에서 동작한다.


1.2 주요 내용

① 18단계 Pipe-and-Filter 파이프라인: 거시 레짐 판단 → 종목 선택 → 비중 배분 → FIRE 역산 → Monte Carlo 시뮬레이션 → 절세 최적화 → 행동 편향 탐지 → AI 스토리텔링까지 일관된 파이프라인으로 처리한다.

② FIRE 역산 엔진: PMT 공식 기반으로 린(월 120만원) / 일반(월 250만원) / 팻(월 500만원) FIRE 달성 나이와 부족 시 필요 추가 적립금을 계산한다.

③ Monte Carlo 시뮬레이션: 1,000회 반복으로 P10/P50/P90 배당 성장 밴드를 산출하고 거시 레짐(금리 상승/하락/중립)에 따라 시나리오를 자동 조정한다.

④ MPT 효율적 프론티어: 5,000회 랜덤 샘플링으로 샤프 비율 최대 포트폴리오를 도출하고 2D 산점도로 시각화한다.

⑤ 2026 세법 반영 절세 최적화: ISA 연 납입 4,000만원 한도, 일반형 비과세 500만원, 청년형 1,000만원 기준으로 최적 절세 전략을 자동 계산한다.

⑥ Survival 리스크 모델: 한국 배당주의 배당 삭감 위험을 Survival 분석 기반으로 예측한다. XGBoost 런타임 의존성을 제거하고 경량 모델로 대체하였다.

⑦ AI Portfolio Advisor: 로컬 Ollama qwen3:14b(14B 파라미터) LLM으로 포트폴리오 자연어 분석 리포트를 생성한다. 외부 API 비용이 발생하지 않는다.

⑧ 포트폴리오 A/B 비교, 인터랙티브 시뮬레이터, 백테스팅(2015~2024), 배당 달력 히트맵 등 10종 이상의 분석 기능을 제공한다.


1.3 기대 효과 및 활용 방안

개인 투자자는 나이·투자금·목표 월배당만 입력하면 맞춤형 포트폴리오와 FIRE 달성 로드맵을 얻을 수 있다. 로컬 LLM 사용으로 개인 재무 정보가 외부로 유출되지 않으며, 월 구독료·API 비용이 발생하지 않는다. 장기적으로 배당 투자 자동화 플랫폼, 금융 교육 도구, 개인 자산관리 앱으로 확장 가능하다.

2. 국내·외 관련 분야 현황

국내 서비스(뱅크샐러드, 토스증권, 미래에셋 연금계산기)는 현재 잔고 조회 및 단순 추천에 집중하며 목표 기반 역산 기능이 없다. 해외 서비스인 Personal Capital, Dividend.com은 미국 자산 중심으로 한국 세법·DART 데이터를 지원하지 않는다. 기존 AI 기반 로보어드바이저(에임, 핀트)는 ETF 중심 분산투자를 추천하나 배당 현금흐름 역산 기능이 없다.

본 시스템은 ① 목표 월배당 역산(FIRE 엔진), ② DART 기반 한국 배당주 데이터, ③ 2026 한국 세법 절세 자동화, ④ 완전 로컬 AI 분석(Ollama), ⑤ Survival 리스크 모델 등 기존 서비스에 없는 기능을 결합한다는 점에서 차별화된다.

4. 프로젝트 설계 및 구현

4.1 아키텍처

본 시스템은 Pipe-and-Filter 패턴을 핵심 아키텍처로 채택한다. 사용자 요청(나이, 투자금, 목표 월배당, 리스크 성향 등)이 입력되면 18개의 필터가 순차적으로 실행되며, 각 필터는 공유 컨텍스트(PipelineContext)를 통해 이전 필터의 결과를 읽고 새로운 결과를 기록한다. 필터 실패 시 파이프라인은 오류를 기록하고 계속 진행한다.

파이프라인 18단계:
MacroRegimeFilter(거시 레짐) → AxisWeightFilter(4축 가중치) → AssetPickerFilter(종목 선택) → WeightAllocatorFilter(비중 배분) → SummarizeFilter(현금흐름 요약) → ProjectionFilter(배당 성장 예측) → RebalancingFilter(리밸런싱) → StressTestFilter(스트레스 테스트) → SectorExposureFilter(섹터 노출도) → CalendarFilter(배당 달력) → RiskAlertFilter(리스크 경보) → FireEngineFilter(FIRE 역산) → MonteCarloFilter(Monte Carlo) → TaxOptimizerFilter(절세 최적화) → BehavioralFinanceFilter(행동 편향) → PortfolioHealthFilter(건강도) → SHAPExplainerFilter(리스크 설명) → StorytellingFilter(자연어 요약)

프론트엔드(React 18)는 REST API를 통해 FastAPI 백엔드와 통신하며, 9개의 전문 시각화 컴포넌트(MonteCarloChart, BacktestChart, EfficientFrontierChart, DividendCalendarHeatmap, CashflowMilestone, HealthRadarChart, AdvisorPanel, CompareView, InteractiveSimulator)가 분석 결과를 렌더링한다.


4.2 설계도

■ REST API 엔드포인트
  POST /api/portfolio/recommend   — 18단계 파이프라인 실행, 포트폴리오 추천
  POST /api/portfolio/backtest    — 2015~2024 백테스팅 (CAGR / MDD / Sharpe)
  POST /api/portfolio/optimize    — MPT 효율적 프론티어 (샤프 비율 최대화)
  POST /api/portfolio/fire-reverse — FIRE 달성 나이·필요 적립금 역산
  POST /api/portfolio/advisor     — AI 분석 리포트 (Ollama LLM / rule-based fallback)
  POST /api/portfolio/compare     — A/B 포트폴리오 비교 분석
  GET  /api/stock/{code}          — 종목 상세 정보 + Survival 리스크 예측

■ DB 주요 테이블
  KrYieldCache     — 한국 배당수익률 캐시
  MLPrediction     — Survival 리스크 예측 결과
  PortfolioHistory — 포트폴리오 추천 이력


4.3 구현 화면

[그림 1] 포트폴리오 비교(Compare) 화면 — A/B 두 전략을 나란히 비교. 레이더 차트(안정성·성장·현금흐름·균등성·물가방어·분산도 6축), 우세 횟수 카드, 세후 월배당·목표달성률·CAGR 등 지표 비교 테이블.

[그림 2~7] 포트폴리오 추천 결과, Monte Carlo P10/P50/P90 차트, 백테스팅 막대차트, MPT 효율적 프론티어 산점도, FIRE 마일스톤 진행바, AI 분석 리포트 화면.


4.4 문제점 및 시행착오

① Monte Carlo p50_monthly 타입 오류: run_monte_carlo()가 시계열 리스트를 반환하는데, advisor_service.py에서 스칼라로 처리하여 TypeError 발생. _scalar() 헬퍼 함수(리스트면 마지막 값 사용)를 도입하여 해결하였다.

② XGBoost 런타임 의존성 제거: 배포 환경에서의 패키지 충돌 문제를 해결하기 위해 배당 삭감 예측 모델을 Survival 모델로 전환하였다. 기존 kr_3class_model.pkl은 벤치마크용으로 보존하였다.

③ Axios 타임아웃: 로컬 14B LLM 추론이 약 74초 소요되나 기본 타임아웃이 10초로 설정되어 항상 실패하였다. AdvisorPanel 컴포넌트의 해당 요청만 120초로 오버라이드하여 해결하였다.

④ React useState 초기화 문제: InteractiveSimulator 슬라이더가 portfolio prop 도착 전에 0으로 초기화되어 고정되었다. useEffect로 portfolio 변경 감지 후 동기화하는 방식으로 해결하였다.

⑤ BacktestChart 422 오류: 백엔드 엔드포인트가 {portfolio: <전체 결과>} 형태를 기대하는데 필드를 평탄화하여 전송하였다. 요청 구조를 수정하여 해결하였다.


4.5 추후 개선 방향

① 실시간 배당 데이터 갱신: 현재 DART 정적 캐시 기반이므로, 주기적 크론 작업으로 최신 배당 공시를 자동 반영한다.

② LLM 스트리밍 응답(SSE): Server-Sent Events 도입으로 74초 대기 없이 실시간 생성 텍스트를 표시한다.

③ 한국 개별주 유니버스 확장: 현재 61개 자산에서 DART 배당공시 기반으로 자동 편입한다.

④ 모바일 반응형 UI 개선: 현재 데스크톱 중심 레이아웃을 모바일에서도 최적화한다.

⑤ 추세 피처 기반 ML 성능 개선: payout_ratio·FCF margin의 3년 slope 피처를 추가하고 walk-forward OOS 검증으로 배당 삭감 예측 ROC-AUC 0.55 → 0.65 이상 목표.
